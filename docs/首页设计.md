2. 场景刚需强度

**定义**

**适合回答**
这个赛道是不是“真需求”，还是只是 AI 玩具？

**可评分信号**（例子：AI Coding 的场景刚需通常高，因为开发者每天都写代码、调试、查文档，且企业有明确预算。 AI 头像生成的场景刚需可能较低，因为更多是低频消费型需求。）
信号	判断方式
是否替代高成本人工	视频剪辑、客服、代码开发、法务审阅

是否对应明确岗位（明确预算）	PM、设计师、开发者、营销、销售、客服
是否有明确付费主体（明确预算）	企业、团队、创作者、开发者

**定义**（这个赛道是不是容易被底层模型更新、平台封禁、API 调价或政策变化影响？）
赛道内产品是否高度依赖少数底层模型、平台 API、第三方生态或政策环境。

**可评分信号**（AI 效率工具依赖较小）
信号	示例
是否依赖 OpenAI、Claude、Gemini、Replicate 等 API	Wrapper 风险
是否依赖单一平台	TikTok、Shopify、Chrome、Slack
是否依赖版权敏感数据	AI 视频、AI 音乐、AI 图像
是否有自研模型/开源模型	降低依赖
是否支持多模型切换	抗风险能力更强

**需求字段**
model_dependency

api_dependency
platform_dependency
.....

**评分方式**（确定好字段，模型来设计权重和算法）

**说明**
这个分数越高，风险越高。它适合和“能力突破密度”一起看：
* 能力突破高 + 技术依赖风险低：优质赛道；
* 能力突破高 + 技术依赖风险高：机会大，但不稳定；
* 能力突破低 + 技术依赖风险高：谨慎。
